# 历史更新公告数据

KIVAO 已移除独立更新公告的阅读入口和后台编辑器，发布通知统一使用系统公告。已有 `updates` 配置与媒体资源保留，修改其他外观设置不会清空它们；不增加数据库迁移。以下记录旧版功能与仍保留的数据、资源合同，不再对应当前 KIVAO 操作入口。

在「站点及外观 → 更新公告」编辑公告，点击页面顶部「保存修改」统一保存。KIVAO 的顶部与侧栏复用同一账户卡片，普通入口固定为「更新公告」：关闭或未发布内容时显示“暂无已发布的产品公告”，不回退上游原始日志或暴露内部构建版本；开启后显示已保存的当前版本与公告内容，不内置虚构的 KIVAO 发布记录。

管理员账户卡片另有「技术更新记录」，后台桌面和移动端品牌入口也可查看源码随附的上游记录与真实构建版本。该入口及弹窗均按已恢复会话中的管理员角色判断，未登录、普通用户和认证未完成时不显示；账号切换后重新判断。前端显隐不代表静态上游日志具有保密性。后台「系统更新」仍使用原管理 API、真实程序版本和 Release 信息，本轮不改变它或启用 Host Updater。

支持最多 30 个版本；每个版本有版本号、可选标题与发布日期，以及最多 50 个可排序的文字、图片、视频内容块。文字支持换行、列表和 Markdown 加粗，原始 HTML 不执行。内容块可选择整行或半行，相邻半行并排，窄屏自动单列。编辑区域提供即时预览，视频手动播放。

图片支持 PNG、JPEG、WebP，最大 10MB；视频支持 MP4、WebM，最大 256MB。媒体使用现有平台资源存储，管理员身份、文件真实 MIME 和新资源归属均由服务端校验。未保存媒体只能由上传管理员预览；已保存媒体可由其他管理员预览；公开读取仅允许当前已启用公告引用的媒体，支持视频 Range 请求。关闭开关保留全部自定义内容及素材引用保护，公共外观响应不返回关闭的公告正文。

当前版本必须对应已添加的版本，版本号不能重复，空文字或未上传媒体不能提交；正文总大小最多 200KB，外观 PATCH 请求上限 512KB。保存成功后同步本页公共状态，其他页面在激活、聚焦或打开公告时重新读取；读取失败保留已有状态，过期响应不能覆盖较新的保存结果。慢刷新期间也不会把技术日志当作产品公告展示。

配置保存在现有 `system_settings` 的 `appearance` JSON 的 `updates` 中，外观合同版本仍为 10；不增加数据表或数据库迁移。恢复默认外观会清空自定义公告并关闭开关，普通入口显示公告空态，管理员仍有独立技术记录入口；已上传媒体仍保留在存储资源中。

媒体接口：`POST /admin/settings/appearance/assets/update-image|update-video`；管理员预览 `GET /admin/settings/appearance/updates/:id`；公开读取 `GET /public/appearance/updates/:id`。公开媒体不接受任意外部 URL，只从当前公告引用的资源生成访问地址。
