# 代码功能地图

## 商品套图

- `internal/ecommerce/contracts.go`、`presentation.go`：原图用途、两阶段提示词及严格 JSON 结果合同；策划与原生出图共用安全排版、已审阅文案和人物摄影边界，不依赖 Provider 或数据库。
- `internal/app/ecommerce.go`、`ecommerce_tasks.go`：项目/轮次、revision CAS、原生报价、稳定请求回执、任务绑定与积分预占事务；`internal/service/aliases_ecommerce.go` 为 handler 的稳定导入面。
- `internal/repository/ecommerce.go`、`internal/model/models_ecommerce.go`：两张新增表、分页历史、结构化存储额度和资源引用保护；迁移注册在 `internal/database/migrations.go` 的 KIVAO v80。
- `internal/handler/ecommerce.go`：登录态商品 API 与管理员阶段设置；合同在 `openapi.yaml`。通用任务入口拒绝伪造商品项目；重试需返回商品页重新确认报价。
- `web/src/pages/ecommerce/`：商品资料、原图/素材库、方向与方案、图片参数、下载、独立轮次；`ecommerce-intents.ts` 负责账号隔离的请求暂存和 UNKNOWN 恢复。
- `web/src/pages/admin/ecommerce-settings-page.tsx`：两个文本阶段的平台模型配置；开放开关沿用 `feature_availability`。
- `internal/app/ecommerce_execution_test.go`：通过本地 HTTP Stub 验证原生 worker、两文本阶段、图片转存、积分结算及素材登记，不调用真实模型。

## 画布与素材稳定性

- `web/src/lib/canvas/canvas-storage-revision.ts`：快照合并及明确删除墓碑。
- `web/src/pages/assets/asset-transfer.ts`、`asset-library-bulk.ts`：素材包资源重建、跨账号检查与全量分页操作。
- `web/src/lib/canvas/canvas-reference-image-size.ts`：面板和生成共用的参考图比例选择；显式尺寸优先。
- `web/src/components/canvas/canvas-mention-hover-preview.tsx`、`canvas-mention-editable.ts`：悬停预览、引用边界、选区及异步引用重绘；标题摘要在 `canvas-generation-title.ts`。
- `backend/internal/app/task_output.go`、`web/src/lib/generation-task-billing.ts`：订单计费摘要与费用展示，不修改结算规则。
- `web/src/components/canvas/canvas-node-text-edit-dialog.tsx`、`canvas-node-text-detection.ts`：手动识别入口、能力/计费说明及切图后的旧结果隔离；提交仍在 `use-canvas-media-tools.ts`。
- `plugin-packages/package-directories.mjs`：文档嵌入与发行打包共用的唯一来源选择。
- `backend/internal/app/logical_models.go`、`logical_models_admin_test.go`：后台列表按模型隔离配置解析失败，保留管理员权限和数据库错误语义。

## 坤肉视频直连

- `plugin-packages/kivao-kunrou-video/` 与同名 `.yingce-plugin`：沿用原插件 ID 的供应商直连版本；Veo/Omni、Grok 使用 `/v1/videos`，SD 使用 `/v1/tasks/sora`，统一查询任务，并按直链或同源鉴权接口下载结果。
- `backend/internal/protocol/kunrou_direct_video_plugin_test.go`：九个型号的请求字段、旧中转模型名拒绝、Google 原有参数限制、Grok 音频开关、SD 素材 URL 及本地 Stub 创建/查询/下载回归。未修改协议宿主或数据库。

## 坤肉 Chat 音频

- `plugin-packages/kunrou-chat-audio/` 与同名 `.yingce-plugin`：独立音频协议，向 Chat Completions 提交非流式请求，从 `data[].url` 提取音频；复用宿主安全下载，不修改通用 Speech、文本 Chat 或异步协议。
- `backend/internal/protocol/kunrou_audio_plugin_test.go`：实际插件包加载、五模型请求、可选音乐参数与参考图、无效选项拒绝、HTTP Stub 音频下载及失败响应回归。

## 易支付多支付方式

- `backend/payment-sdk/methods.go`：开放方式与默认值校验；`payment-plugins/epay.go`：选择映射到单个上游 `type` 并签名。`internal/app/payment.go`：订单固定方式、幂等检查与刷新；`internal/database/migrations.go`：Schema 79。
- `web/src/pages/admin/payments/payments-page.tsx`：配置多选；`components/layout/workspace-wallet-topup.tsx` 与 `workspace-wallet-modal.tsx`：用户选择；`components/payment/use-payment-order-flow.tsx`：提交方式及重置幂等键。

## 视频深度动作捕捉

- `plugin-packages/volcengine-mediakit-video-depth/`：独立深度协议、幂等提交和异步结果映射；同名 `.yingce-plugin` 为后端加载包。原 `volcengine-mediakit/` 仅提供画质增强。
- `backend/internal/app/video_processing.go`：按资源归属、就绪状态、实测时长与尺寸准入，隔离增强参数；`model_capability*.go` 和 `model_router.go`：独立能力、上限和 `depth_capture` 计价选择；`logical_models.go` 只为声明了分辨率的模型投影清晰度默认值，避免隐藏无清晰度选项的处理模型。
- `web/src/components/canvas/canvas-video-depth-panel.tsx`、`lib/canvas/canvas-video-depth.ts`：节点下方确认面板、源校验、报价与任务参数；`pages/canvas/use-canvas-media-tools.ts` 和 `use-canvas-generation-retry.ts`：草稿连线、开始后消费到同一节点及重试；`use-canvas-generation-executor.ts` 阻止专用节点误入普通生成。
- `web/src/pages/canvas/canvas-project-world-layers.tsx`：从单选状态派生唯一活动视频，`project.tsx` 承接静态预览播放按钮的选中动作；现有 `components/video-player.tsx` 保持单次自动播放尝试及手动暂停语义。
- `backend/internal/workbench/catalog.go`、`service.go`、`tasks.go`：工作台执行方式与单视频合同、管理及请求约束；`app/workbench_bridge.go` 在选价前按资源记录准入。`web/src/pages/admin/workbench-tools/workbench-tools-page.tsx` 配置执行方式；`pages/workbench/image-workbench-page.tsx` 复用视频工作台上传/素材库、专用模型、实测时长报价及结果/任务展示。

## 插件统一管理与导出

- `backend/internal/app/plugin_management.go`：所有插件的后台全局状态、管理员权限、审计及旧个人启停接口拒绝；不迁移历史用户配置。
- `web/src/components/layout/client-root-init.tsx` 与 `web/src/stores/use-plugin-store.ts`：初始化内置应用、同步服务端开关、窗口激活与定期刷新，状态缺失时不启用。
- `web/src/pages/admin/plugins/plugins-page.tsx`：唯一插件启停页面；路由、侧栏和素材选择器不再开放前台插件及 Eagle 入口。
- `web/src/lib/canvas/canvas-export.ts`、`web/src/types/canvas-export.ts` 和 `web/src/pages/assets/asset-transfer.ts`：原生 ZIP 导出标识 `kivao` 及素材包导入校验。

## 统一认证弹窗

- `web/src/components/auth/auth-dialog-layout.tsx`：路由根节点的唯一弹窗、登录/注册/找回密码切换、旧链接承接；`require-auth.tsx` 保留权限门禁并在当前页面请求登录。
- `web/src/pages/auth/login.tsx`、`register.tsx`、`forgot-password.tsx`：复用正式表单、验证码、协议及认证 API，支持成功回调；`lib/auth-navigation.ts` 校验站内返回目标。
- `web/src/stores/use-auth-dialog-store.ts`：共享弹窗状态，以及只在内存中、按确认账号和路径读取的游客文本草稿；首页与工作台恢复后清除。旧 `CreationLoginDialog` 简化登录实现已移除。

## 公告、个人存储与画布助手

- `components/layout/system-announcement-center.tsx`：用户系统公告入口；账户卡片与侧栏已移除独立更新公告，`pages/admin/settings/appearance-settings-page.tsx` 不再编辑旧更新公告但保存时保留历史配置，后台品牌入口返回首页。
- `web/src/lib/oss-settings.ts`、`components/layout/user-oss-settings-form.tsx` 与 `backend/internal/app/settings.go`、`storage_location.go`：个人对象存储默认前缀及保存/测试的统一回退，旧配置保持原值。
- `web/src/layouts/user-layout.tsx`、`components/canvas/canvas-cloud-agent-panel.tsx`：单一实例与画布可见性；`lib/canvas/agent-panel-dock.ts`：默认右侧停靠，保留已有偏好和窄屏回退。

## 技能公开审核与上下架

- `backend/internal/skills/skill_review.go`、`repository/skill_review.go`：管理员审核、版本并发检查、审计事务与审核列表；`skills.go`、`skills_agent.go` 的共享可见性约束覆盖目录、运行时和原文件读取。
- `backend/internal/database/skill_publication_migration.go`：v78 将历史用户公开技能纳入审核，复用状态列，不删除技能或用户关系。
- `web/src/pages/admin/skill-review-page.tsx`：审核列表和阅读器操作；`services/api/skills.ts`：审核 API，`pages/skills/`：申请公开和作者状态提示。

## 技能阅读预览

- `web/src/lib/skills/skill-markdown.ts`：仅为预览提取 Markdown 正文；`web/src/pages/skills/skill-detail-drawer.tsx` 的 `SkillMarkdown` 同时供技能详情和技能工作台使用，源码与文件 API 保持原样。

## 工作台素材分组与一键生成

- `web/src/lib/workbench-template.ts`：按输入区 key 生成 `@` 引用、展开整组素材、统一各媒体类型编号，以及安全的任务展示摘要。
- `web/src/pages/workbench/workbench-references.ts`：上传和素材库共用的数量、类型与去重校验，以及旧本地素材的资源保存；页面复用 `AssetLibraryPickerModal` 选择远端分页和本地缓存素材。
- `web/src/lib/workbench-inputs.ts` 与 `backend/internal/workbench/inputs.go`：效果专用/通用素材与注意事项设置，前端显示、预设引用和后台校验共享既有 JSON 配置；后端按效果校验任务素材，不新增数据库结构。
- `backend/internal/workbench/default_examples.go`：按图片/视频分类读写默认作品示例，复用已有系统设置、资源归属校验、展示 URL 及审计；未选择场景时由工具目录一并返回。
- `pages/admin/workbench-tools/workbench-tools-page.tsx` 复用画布引用编辑器维护模板；`pages/workbench/image-workbench-page.tsx` 同时负责图片/视频的素材表单、执行提示词拼装和再次生成；`pages/tasks/` 复用摘要展示。
- `backend/internal/workbench/tasks.go` 保留原模板和补充要求快照，继续校验资源归属、输入数量及角色；`internal/app/task_output.go` 投影任务列表所需的工具名称、效果和素材数量。不新增数据表或迁移。
- `pages/workbench/workbench-batches.ts`：批量拆单、报价次数、任务归组与未知结果状态；`workbench-batch-status.tsx`：回执查询、续提和取消未提交项；`workbench-batch-storage.ts`：账号及工作台类型隔离的意图暂存、字段白名单和刷新恢复。`image-workbench-page.tsx` 保留现有页面，系统渠道及逻辑模型接入批量流程。
- `pages/workbench/workbench-image-results.tsx`：解析单任务全部图片产物，结果区与详情区共用多图网格；成功摘要缺少完整产物时只读补取所选任务详情，同一任务版本的普通轮询不重取，切号/切任务/卸载取消请求，失败可显式重读；单图继续使用原预览。`workbench.css` 的底部模型栏分行，报价和生成按钮不互相挤压。
- `backend/internal/app/workbench_batch.go`：批次身份、请求指纹、当前用户回执查询及完成输入精简后的指纹保留；`workbench_bridge.go` 组合领域校验与任务创建，私有 `CreateTaskRequest.workbenchTaskID` 固定任务主键。沿用仓储事务中的任务主键与积分预占回滚，无 Schema 变更；`handler/workbench.go` 和 `openapi.yaml` 提供回执 GET 合同。

## 短剧自动制作

- 纯逻辑：`backend/internal/production/`（作品圣经、分集与剧本提示词 `prompts.go`，模型输出解析 `parse.go`，分镜规则与时长 `storyboard.go` / `timing.go`，按视频模型上限切剧情段 `SegmentShotsForVideo`，段提示词素材稿 `segment_prompt.go` 与撰写要求 `segment_writer.go`，参考图方案 `assets.go`，用户分镜表直接导入 `storyboard_import.go`，原文台词逐句核对 `dialogue_check.go`）。
- 调度循环：`backend/internal/app/drama_orchestrator.go`（同步任务结果 → 推导工作 → 按优先级派发，租约保证单项目单循环；成片时间线由各段视频拼接）；剧情段视频请求的组装、提交、回写与最后一帧抽取在 `drama_segment_video.go`（`prepareDramaSegment` 同时供预览与提交使用）。
- 服务与用户操作：`app/drama_service.go`（创建、摘要、单集详情与剧情段视图）、`drama_actions.go`（审阅、镜头编辑、段提示词与段视频、设定重做、放行）、`drama_editing.go`（逐集追加、原文与素材类型修改、插入 / 删除镜头、上传并锁定参考图、台词核对）、`drama_models.go`（模型目录、视频能力 `dramaVideoProfile`、报价预估）；类型在 `drama_types.go`。
- 持久化：`model/models_drama.go`、`repository/repository_drama.go`（调度与用户写入均为列级条件更新）；迁移 v61–v67、v71、v73 在 `database/migrations.go`。HTTP：`handler/drama_routes.go`。
- 渲染：`app/timeline_render_plan.go` / `task_render.go` 用 ffmpeg 合成，保留段视频自带的声音。
- 前端：`web/src/services/api/drama.ts`；`pages/projects/index.tsx`（作品列表）、`create.tsx`（上传与预估）、`detail.tsx`（制作台）。制作台子组件在 `pages/projects/studio/`：`storyboard.tsx`（剧情段卡片）、`segment-dialog.tsx`（剧情段弹窗：段视频、生成依据、镜头脚本与完整视频提示词）、`segment-parts.tsx`（状态、视频与生成依据共用组件）、`panels.tsx`（设定、待处理、制作设置）、`final-view.tsx`、`script-view.tsx`、`job-detail.tsx`；样式 `drama.css`。模型选择复用通用 `ModelPicker`（`drama-model-picker.tsx`、`lib/drama/model-choice.ts`）。
- 回归：`internal/production/production_test.go`、`app/drama_orchestrator_test.go`、`app/drama_storyboard_test.go`、`app/drama_assets_test.go`、`web/src/lib/drama/*.test.ts`。
- 精修画布（后端）：`app/drama_canvas.go`（作品的精修画布、投送媒体的素材登记、版本记录与来源、段视频采用与尾帧补抽、画布花费计入预算 `dramaTotalSpent`、画布任务预算闸门 `ensureDramaCanvasBudget`）、`repository/repository_drama_canvas.go`（画布花费汇总、段视频采用事务、短剧持有资源的引用 `DramaResourceReferences`）；尾帧抽取与视频时长读取在 `drama_segment_video.go`（`saveDramaTailFrame`、`inspectDramaVideo`）。Agent 工具 `drama_get_context` / `drama_adopt_canvas_media` 在 `app/cloud_agent_drama.go`，只在 `Scope.Drama`（运行画布关联短剧）时暴露。
- 精修画布（前端）：投送的纯函数在 `web/src/lib/canvas/drama-canvas-projection.ts`（节点、段框、时间线、过期判断、分镜转短剧原文），副作用在 `web/src/services/drama-canvas.ts`（找到或新建精修画布、跳转参数、素材登记、分镜画布关联到新短剧）；画布页编排 `pages/canvas/use-canvas-drama.ts`，侧栏 `components/canvas/canvas-drama-sidebar.tsx`，采用弹窗 `components/canvas/canvas-drama-adopt-modal.tsx`。查询键 `lib/drama/drama-query-keys.ts` 与文案 `lib/drama/drama-format.ts` 由制作台和画布共用；制作台入口 `studio/use-studio.ts` 的 `useOpenDramaCanvas`，版本记录 `studio/take-list.tsx`。

## 后端调用链

AutoDL 画面规格由 `app/model_capability_screen_spec.go` 读取官方插件工作流合同（精确工作流优先，未声明的 ID 回退到 `*` 默认预设），校验所选分辨率及默认值，允许自定义标签；`task_creation.go` 在价格选择之前归一化，任务校验与 `provider_video.go` 再次使用同一规则。前端 `lib/video-screen-specs.ts` 管理插件预设、所选规格与工作流切换，`ModelCapabilityEditor` 复用到系统及自定义渠道；无开关或独立草稿。

```text
HTTP 请求 -> handler -> service（稳定导入面 / 别名）-> app（组合根）-> 业务域包 -> repository/model
                                                                     |
                                                                     -> protocol / payment / generation / outbound
```

`internal/service` 只再导出 `internal/app` 的类型、常量和包级函数，handler/cmd 仍 import `internal/service`。组合根和尚未拆出的业务实现在 `internal/app`。已抽出的域包不得 import `service` 或 `app`（防回环）。共享错误码与 ID/字符串工具在 `internal/kernel`。

## 修改原则

- HTTP 参数与响应只在 handler 处理，业务规则进入 service。
- 页面保留流程协调；可独立理解和测试的算法进入同业务域的 `lib`。
- 新增功能时只更新本页的主要入口，不增加逐文件清单。
