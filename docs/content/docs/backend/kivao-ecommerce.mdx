# 商品套图

先识别商品、选视觉方向，再策划整套图片。当前只做商品主图和详情图，复用已有平台模型、任务、积分与素材能力。

## 配置与使用

1. 管理员在“商品套图”配置商品识别、整套策划两个文本阶段模型。可使用同一模型，但必须开启图片参考能力，且使用者的分组也有权访问。配置不包含连接信息或密钥。
2. 在“功能开放”启用商品套图与图片生成。商品套图默认关闭；关闭后可继续通过已保存的项目链接查看、下载既有作品。
3. 进入 `/ecommerce`，填写商品信息，上传或从素材库选择 1–8 张图片。至少一张为商品原图，可区分商品细节和风格参考；风格图不作为商品身份或事实依据。
4. 点击识别并确认报价，获取 4 个视觉方向。选择后，点击整套策划并再次确认报价；两个文本阶段也计费，不自动执行下一阶段。
5. 使用策划方案，选择平台图片模型及其实际支持的参数，确认逐张或整套的报价后生成。每张使用一个原生图片任务，不绕开模型引用数量、定价和账户限制。
6. 可以编辑每张的标题、文案和提示词，再次报价后重新出图。原任务和较早作品保留，可展开查看下载；生成成功但保存失败时使用“重试保存”，不重复调用模型。
7. 下载单图或已完成图片的 ZIP。新建一轮会归档当前轮的资料、方案和任务引用，旧轮单独分页，不把历史嵌套复制进下一轮。

没有质量评分阶段，不引入全站助手、知识库种子、技能自动安装或独立 Agent 运行时。它是针对当前 KIVAO 任务接口的最小适配，不承诺兼容上游完整电商模块的 API 或数据表。

## 中断与并发

提交前会在当前用户范围的浏览器数据库保存本次确认的请求。收不到回执时保留 UNKNOWN，先查询原回执，再允许用户重试原请求；不得更换请求标识自动重新生成。读取失败或本地存储不可用会阻止新发送，不能用“本地已保存”冒充服务端受理。

不同账号隔离暂存、查询和资源；切换页面/账号后，旧异步流程停止后续发送。刷新、打开项目/历史只读取，不自动恢复生成。已确认但尚未提交的余项必须明确点击继续，报价过期重新确认；结束未提交项不会删除已受理任务。多处同时修改以项目 revision 拒绝覆盖。

未确认请求查询为空后，可明确选择“终止待确认请求并新建一轮”。页面先读取项目 revision，再次查询原回执；发现原任务则恢复回执，未发现才以该 revision 原子新建轮次，成功后才清除暂存。迟到的原任务和终止操作只能有一个写入成功；并发冲突、响应丢失或本地清理失败继续保留待确认记录，不凭等待时长判断未受理。

## 数据与发布边界

需要 KIVAO Schema 80 的项目与轮次两张新表，既有 78/79 不改；前后端需配套发布。备份仍须包含 PostgreSQL 逻辑快照、完整 Backend data 和原 `.settings-key`、资源文件、配置及固定镜像锁。

升级后严格要求 Schema 79 的旧应用不能直接启动。发布前必须准备并验证支持 Schema 80、可关闭商品套图的应用回退候选，或单独授权并演练一致性备份恢复；禁止自行降低账本版本、删除新表或覆盖新写入。

当前验证只覆盖本地虚拟模型及隔离数据库。真实模型的结构化结果稳定性、商品身份/文案质量、按 token 实收和真实供应商异常费用仍需在后续单独授权后验收，不属于本轮生产放行。
