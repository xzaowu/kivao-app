记录于 2026-11-16，代码基线 `f87821f636f74157a92e1f059cc76709a6fb3f8e`。以下优化先完成本地实施与验证；所有者随后授权发布这批性能改动。实际发布与生产验收以对应固定 SHA 的私有运行记录为准，不进行真实模型／支付调用。历史生产抽样用于定位问题，本地验证不代表生产已加速。

## 1. 积分中心打开缓慢

已核实：

- 前轮生产日志的 13 次 `GET /api/payments/providers` 均成功，耗时约 2.85–3.27 秒。现有五份支付插件与当前镜像内置包身份一致，没有发现旧支付定制残留。
- `web/src/components/layout/workspace-wallet-modal.tsx` 每次打开都会重新请求套餐、支付渠道和支付设置；`Promise.all` 等全部完成后才结束充值区加载状态。
- `backend/internal/app/payment_providers.go` 遍历支付渠道时反复调用 `s.Plugins()`；`backend/internal/app/protocol_plugins.go` 的 `list()` 每次重新解析全部插件 manifest。当前登记 118 个插件，重复工作已确认，但尚未用性能剖析量化其耗时占比。

本地已实现：

- [x] 用户和管理员渠道列表每个请求只解析一次插件清单，空列表不解析。快照不跨请求保存，下一次请求看到插件停用、配置和权限变化。
- [x] 套餐、渠道、汇率独立查询；套餐先显示，不等最慢的渠道。按账号缓存 30 秒，闲置 2 分钟回收；重新打开仍刷新余额。支持刷新与错误重试，配置刷新中或失败时不能下单，支付写入仍由后端校验实时价格和渠道。
- [x] Stub 专项覆盖慢渠道、缓存重复打开、过期刷新、配置错误与恢复、账号隔离、在途取消；后端专项覆盖权限、密钥脱敏及配置更新可见性。

合成基准（118 份约 24 KiB 清单、5 个渠道、3 次）：重复解析约 325.44 ms／49.83 MB → 请求内快照约 20.24 ms／3.32 MB。仅插件解析热点约加速 16 倍、分配减少 93.3%，不能换算为生产打开积分中心的耗时。

这属于应用代码优化，不是删除插件或调整某个后台开关即可修复。生产固定镜像内不做临时文件补丁。

## 2. 灵感广场媒体与目录加载

本轮代码和公开 HTTP 抽查：

- `backend/internal/inspirations/service.go` 设置正常同步间隔为 6 小时，公开 feed 在进程内缓存 5 分钟。同步的是条目和媒体地址，不是将外部图片／视频下载到本站；前端另有每日推荐排序。
- 生产公开 feed 返回 309 条，图片来自 `media.goodcase.ai`、`cms-assets.youmind.com`，视频来自 `media.goodcase.ai`。静态目录另有本站缩略图和 `www.haohaoxue.com` 等外链。
- `web/src/services/inspiration-catalog.ts` 等待三份完整静态目录、manifest 和 feed 后才构建目录。三份目录加 feed 解压后约 4.23 MB；本次请求携带 `Accept-Encoding: gzip` 时实际合计约 1.64 MB，说明已启用压缩，不能把“开启 gzip”当作未完成项。
- 本地命令行网络抽样中，gzip 请求约 2.3–3.5 秒；这不是用户浏览器实测或服务器处理时长。四个媒体 HEAD 样本均为 200，已有长期缓存与 Range 支持；视频样本约 1.78 MB、4.85 MB，未下载视频正文。不能据此推断所有地区或全部条目的速度。
- `web/src/pages/inspirations/inspiration-example-media.tsx` 已使用 IntersectionObserver 延迟挂载视频地址，但进入视口附近后会请求 metadata，正常播放分支没有设置 poster；外部视频准备慢时，卡片仍可能等待。图片已有 lazy loading。

本地实施与保留项：

1. [x] 目录按来源逐步显示，失败来源单独重试，提示未完成状态；保留搜索、分类、每日推荐。静态来源复用内存缓存，上新 feed 每 5 分钟刷新，失败保留旧内容；旧请求不能覆盖新的失效刷新。
2. [x] 首批三张封面优先，其余图片延迟加载。桌面悬停才请求列表视频，播放前保留封面，离开暂停；手机不请求列表视频。失败有有限重试，详情仍可手动播放和查看原图。
3. [x] 仅已登记封面使用同源受限缓存：新增 `GET /api/public/inspirations/covers/:id`，不接收任意 URL。登记来自构建时静态目录和当前公开 feed；只放行既有 HTTPS 图片主机，并继续使用出站 DNS/IP 防护和重定向校验。失败时浏览器仅回退原封面一次。
4. [ ] 暂不接 CDN 或对象存储，不预下载全库／视频。部署后先观察真实首屏、冷缓存命中和地区差异，再决定是否需要预热热门封面或独立 CDN。

封面压缩已做六张本地样本对比：最大宽度 960px（不放大小图）、WebP Q85 在 320px 卡片显示下未见明显变化，放大细节仍有轻微差异，不属于严格无损。单张体积降幅中位数约 71%；合计降幅 94% 被一张 7.78 MB PNG 拉高，不作为整站预期。640px 版放大后小字与毛发更软；原尺寸无损转码使六张中的五张变大。对比证据在 Git 忽略的 `.local/cache/cover-comparison-20261116/REPORT.md` 与 `results.json`，原图未覆盖。

实际实现复用 Backend 镜像已有 FFmpeg／libwebp，最大宽度 960px、Q85；转码不变小、组件缺失或含色彩配置／方向／动画标记时缓存校验后的原图，已有 WebP 不二次压缩。六张 Pillow 对比的尺寸和耗时不能当作 FFmpeg 实际结果，尤其含 ICC 的样本会保守保留原图。

缓存位于应用数据目录的 `cache/inspiration-covers`，仅可再生公开封面，不写业务资源表。容量上限 256 MiB，最长保留 7 天，24 小时后先返回旧图并后台刷新；浏览器缓存 1 小时，支持 ETag／304。单源 ≤8 MiB、≤1200 万像素，两路下载／转码并发、最多 16 个排队任务；相同封面合并请求、失败冷却 60 秒。完整解码后才存储，编码与滤镜线程受限；落盘原子替换并清理本缓存的异常临时文件。超预算按最旧缓存淘汰，不改用户媒体、原图或视频。冷缓存首次仍需访问源站，不承诺首次立即加载。

维护静态目录后运行 `bun scripts/sync-inspiration-cover-sources.mjs` 更新只含公开 ID／地址的后端登记文件；`--check` 与 Go 专项能发现登记遗漏。管理员上传示例和个人自定义图片不走这个公共缓存。

## 4. 验收与发布边界

实施阶段完成本地专项、类型／构建与受控浏览器验证；具体结果见 `docs/content/docs/progress/pending-test.mdx`。无数据库迁移、依赖升级或收费协议变化。真实地区网络、生产 CPU／内存峰值、长期缓存容量及真机 Safari 待发布验收。本地后端已重新编译并启动，Schema 104 与迁移账本不变；预览容器仍保持禁外网，真实外部封面请求会失败并回退原图，不以它冒充公网缓存验收。

缓存按当前单 Backend 进程设计，不直接扩展为多个进程共享同一目录。构建仍提示部分大 chunk／混合静态动态导入；是否拆包应结合实际首屏性能测量，下轮再决定，不扩大本批为加载架构重构。

验收时分开测目录响应、首屏媒体可见时间、视频悬停首帧、失败恢复、每日上新延迟与真实传输量；先记录浏览器瀑布图，再决定是否需要 CDN 投入。

参考：[视频加载性能](https://web.dev/learn/performance/video-performance)、[版本化资源的 HTTP 缓存](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Caching)。本轮应用 modern-web-guidance 的媒体延迟加载和性能指南，避免列表视频的 metadata 请求争用首屏带宽，并优先请求首屏图片。
