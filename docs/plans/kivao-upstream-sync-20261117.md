1. Schema 从 104 升为 105，新增图片用量计费列；新增 `yingce_schema_migrations` 1–4 与官方资产表。上游只自动识别其特定旧官方资产账本，不代表可以识别任意旧 KIVAO 定制账本。必须用当时的真实备份副本做 PG17 升级、保留字段／密文核对和回滚演练；本轮测试不等于生产迁移授权。
2. 历史一次性 `ImportKivao79` 仍固定目标 Schema 104，源码升级后应拒绝执行（`import_target_version_changed`）；它不是 104 → 105 的升级工具，不放宽版本保护，也不重新迁入旧支付、技能或任务。
3. 部署前检查原插件注册表、深度模型能力及价格选择器。旧插件 ID `volcengine-mediakit-video-depth` 不等于官方插件 ID `volcengine-mediakit-depth`，协议 ID 仍为 `volcengine-mediakit-video-depth`。已有旧配置不会仅靠替换源码自动完成转换；需在隔离副本评估转换或按官方配置重建，保留原始记录并取得对应写入授权。官方插件默认关闭。

5. Schema 变更后不能把旧镜像直接接升级库作为回滚。继续使用 KIVAO 自有 GHCR 固定 digest、原 Compose 组合和 Agent `init: true`；旧发布锁与上游安装器／Host Updater 不用于本轮部署。
6. 真实供应商协议、HEVC 真机播放、CDN／公网加载、真实支付和实际账单均留待单独授权验收。技能库管理员权限、新官方素材入口需要产品验收。
