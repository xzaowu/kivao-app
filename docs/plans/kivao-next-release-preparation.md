# KIVAO 下一版部署准备

本文件随 `dev/kivao-next` 本轮产品提交保存，仅记录候选准备，不构成镜像发布、生产备份、迁移或部署授权。建议版本为 1.0.5；尚未创建发布分支、标签或候选镜像。实际候选 SHA 使用提交后的完整 Git SHA，不能用旧版 CI 代替。

## 基线与范围

- 开发直接继承 `aae0d4aa45902540497edb0042fe901fd736e0e1`，没有合并或 rebase main，也没有整体合并上游。
- 最近一次本地生产验收记录是 `kivao-1.0.4-aae0d4aa4590-r1`、Schema 77。本轮没有连接生产，真正发布前仍须重新只读核对。
- 收束已实施的手机工作台布局、创作输入和入口、素材组与效果、注意事项、多个作品示例、工具选择器与灵感大厅；不再增加下一轮功能。
- 包含技能阅读与公开审核、登录弹窗、品牌与公告简化、后台插件统一开关、画布节点开放控制、导出标识和邮箱验证码提示。
- 包含独立深度动作捕捉协议/视频节点/工作台入口、易支付多支付方式，以及已评估的画布同步、反馈附件保护、转换提示和支付 RPC 业务错误修复。
- 易支付候选包为 `official-payment-epay` 1.0.10；深度捕捉拆为 `volcengine-mediakit-video-depth` 1.0.0，原增强插件为 `volcengine-mediakit` 1.2.0。发布构建还需验证实际打包版本、来源及各平台产物，不能只看清单。
- Backend/Agent 依赖锁、前端依赖锁和 Agent Runtime 产品源码没有本轮变更。前端助手展示范围有变化，不代表 Agent Runtime 已升级。

## 必须单独处理的迁移与回滚

| 版本 | 本轮变化 | 数据影响 |
| --- | --- | --- |
| 78 | `skill_publication_review` | 历史用户公开技能转待审核，私有技能保留；旧内置禁用状态转下架，不删除包文件或收藏关系。 |
| 79 | `payment_order_method` | 新增订单 `payment_method`，历史订单保持空串；不改金额、积分和入账状态。 |

这次不是免迁移更新。旧应用严格要求 Schema 77，不能在 79 的数据库上仅换回 1.0.4 镜像并宣称完成回滚；不得手改迁移账本伪装降级。当前未实施或验证生产数据降级方案，也未授权执行生产迁移。

后续必须先在独立 PG17 中，用经授权取得的最新备份验证 77→79、原 `.settings-key` 解密、模型/积分/支付/媒体完整性及回退方式。维护窗口停写后取得跨数据库与文件一致的恢复点，记录恢复耗时。在回退路径确认前不放行生产。若需要覆盖生产数据库恢复备份，仍须明确授权，并防止覆盖窗口后的新写入。

工具效果素材组、示例、灵感及新资源引用规则虽然主要复用 JSON，旧应用未必识别。回退还要核对配置和资源保护能力，不能只比较 DDL。未来合并上游时需比较迁移名称、校验和与语义；不能仅因版本号相同认定兼容。

## 发布前剩余工作

1. 确认本次提交范围后，再单独授权推送和候选镜像发布。复用现有发布机制，更新精确 SHA、版本、允许变更范围及回滚基线，不新增审批体系。
2. 现有 `.github/kivao-1.0.1.json` 和 `scripts/kivao-release.py` 仍固定 1.0.4、Schema 77 和 `migration_authorized: false`；首发 `kivao-apply-image-lock.py` 也只接受首发版本。它们当前不能用于本候选，禁止绕过校验或只修改环境中的镜像地址。
3. 完成新 SHA 的完整 CI、三个 AMD64 镜像构建和来源验证；经发布授权后才取得 Registry digest，生成候选 release lock 和指向上方 1.0.4 的 rollback lock。本轮不填造候选 digest。
4. 完成上述 PG17 备份恢复、迁移及回退演练；重新只读核实生产空闲任务、订单与回调、空间和原镜像，再申请维护窗口与迁移/切换授权。
5. 真正切换前保留旧 Web 目录，核对入口脚本和静态挂载；只操作三个应用服务，不升级 PG/Redis、不改 Nginx。新服务启动前确认 Schema、迁移账本及 `CANVAS_AUTO_MIGRATE=false` 的实际生效值，禁止入口自动迁移或无意启动 Compose 的 migrate 服务。
6. 候选镜像浏览器验收覆盖管理员/普通用户/游客、明暗主题与手机、素材与示例、技能审核、插件开关、SSE 与 Agent Stub。真实付费模型、火山服务和支付尚未验收，不在本轮调用。

本轮本地检查结果见同次提交的 `pending-test.mdx` 收尾条目；它不能替代新 SHA 的 CI 或候选镜像验收。其余未选取的上游改动、Agent/任务恢复演进及易支付其他协议变更留待下一轮评估，不混入本次准备。
